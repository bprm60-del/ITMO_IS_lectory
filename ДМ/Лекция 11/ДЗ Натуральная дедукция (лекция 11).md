## ЧАСТЬ III. Подробные решения и ответы

### Ответы на контрольные вопросы

#### Ответ на Вопрос 1 ($P \to P$ в нотации Фитча)
Вывод формулы $P \to P$:
```
│ │ 1. P          Гипотеза
│ │ ────
│ │ 2. P          Повторение (Reiteration), 1
│ 3. P → P        →I, 1–2
```
* **Анализ гипотез**: В строке 1 открывается subproof с гипотезой $P$. В строке 3 при применении правила введения импликации ($\to I$) гипотеза $P$ **снимается (discharged)**. Формула $P \to P$ доказана в пустом контексте (без каких-либо открытых гипотез).

---

#### Ответ на Вопрос 2 (Доказательство $(P \wedge Q) \to Q$)
Вывод:
```
│ │ 1. P ∧ Q      Гипотеза
│ │ ────
│ │ 2. Q          ∧E₂, 1
│ 3. (P ∧ Q) → Q  →I, 1–2
```
* **Использованные правила**: 
  1. $\wedge E_2$ (устранение конъюнкции) к строке 1 для извлечения правого операнда $Q$.
  2. $\to I$ (введение импликации) с закрытием subproof 1–2.

---

#### Ответ на Вопрос 3 (Следствие из $P \to Q$ и $\neg P$)
* **Ответ**: Утверждение $Q$ **НЕ следует** из посылок $P \to Q$ и $\neg P$.
* **Контрмодель (контрпример)**:
  Зададим булеву оценку переменных:
  $$\nu(P) = 0, \quad \nu(Q) = 0$$
  Проверим истинность посылок при оценке $\nu$:
  1. $\nu(P \to Q) = 0 \to 0 = 1$ (посылка истинна).
  2. $\nu(\neg P) = \neg 0 = 1$ (посылка истинна).
  Однако заключение $\nu(Q) = 0$ (ложно).
  Так как нашлась оценка, где все посылки истинны, а следствие ложно, семантическое следование не выполняется: $\{P \to Q, \neg P\} \not\models Q$.
  По теореме о корректности синтаксический вывод $Q$ из этих посылок построить невозможно.  
  *(Логическая ошибка вывода $Q$ из таких посылок называется в классической риторике «ошибкой отрицания антецедента» — Denying the Antecedent).*

---

#### Ответ на Вопрос 4 (Вывод $\neg P$ из $P \to \bot$)
Формальный вывод в нотации Фитча:
```
│ 1. P → ⊥        Посылка
│ ────
│ │ 2. P          Гипотеза
│ │ ────
│ │ 3. ⊥          →E, 1, 2
│ 4. ¬P           ¬I, 2–3
```
* **Использованные правила**:
  1. $\to E$ (Modus Ponens) к строкам 1 и 2, дающее противоречие $\bot$.
  2. $\neg I$ (введение отрицания) к диапазону 2–3, закрывающее гипотезу $P$ и производящее $\neg P$.

---

#### Ответ на Вопрос 5 (Отличие $IP$ от $\neg I$)
1. **Правило введения отрицания ($\neg I$)**:
   * Начинается с гипотезы $P$ (без отрицания).
   * Приводит к противоречию $\bot$.
   * Снимает гипотезу $P$ и заключает отрицание $\neg P$.
   * **Является интуиционистским (конструктивным)**: опровержение гипотезы $P$ конструктивно свидетельствует об истинности $\neg P$ (то есть $P \to \bot$).
2. **Косвенное доказательство ($IP$ — Indirect Proof)**:
   * Начинается с гипотезы отрицания $\neg P$.
   * Приводит к противоречию $\bot$.
   * Снимает гипотезу $\neg P$ и заключает утверждение $P$.
   * **Является классическим (неконструктивным)**: оно постулирует существование свидетеля для $P$, не предъявляя его алгоритмической конструкции, опираясь на эквивалентность $\neg\neg P \equiv P$.

---

#### Ответ на Вопрос 6 (Корректность и Полнота)
* **Корректность (Soundness)**: $\Gamma \vdash \varphi \implies \Gamma \models \varphi$. Всё, что доказуемо в исчислении, истинно в семантике. Сбой корректности означал бы, что система логически сломана и способна доказывать ложные утверждения (выводить ложь).
* **Полнота (Completeness)**: $\Gamma \models \varphi \implies \Gamma \vdash \varphi$. Всё, что истинно в семантике, доказуемо формальными правилами. Сбой полноты означал бы, что система слишком слаба: существуют истинные теоремы, доказательства которых в системе построить в принципе невозможно (недостаток правил вывода).
* **Необходимость обеих**: Только одновременная корректность и полнота гарантируют абсолютный изоморфизм синтаксиса и семантики ($\Gamma \vdash \varphi \iff \Gamma \models \varphi$).

---

#### Ответ на Вопрос 7 (Компактность через полноту)
1. Любое формальное доказательство в натуральной дедукции по определению представляет собой **конечный список строк (шагов вывода)**.
2. В конечном числе шагов может фигурировать лишь **конечное подмножество формул** $\Gamma_0 \subset \Gamma$.
3. Если $\Gamma$ невыполнимо, то семантически $\Gamma \models \bot$.
4. По теореме о полноте это влечет синтаксическую выводимость противоречия: $\Gamma \vdash \bot$.
5. Поскольку вывод конечен, он задействует лишь конечное подмножество $\Gamma_0 \vdash \bot$.
6. По теореме о корректности $\Gamma_0 \models \bot$, то есть конечное подмножество $\Gamma_0$ невыполнимо. Контрапозиция дает формулировку компактности: если любое конечное подмножество выполнимо, то и всё множество выполнимо.

---

#### Ответ на Вопрос 8 (Проверка vs Поиск вывода)
* **Проверка готового вывода** — локальна и механистична. Для каждой строки проверяется соответствие единственному указанному правилу. Это занимает полиномиальное время $O(N)$ (детерминированный парсинг и сверка формул).
* **Поиск доказательства** сталкивается с нелокальностью и неопределенностью выбора: на каждом шаге существует бесконечно много возможных формул для гипотез subproof или применения правил устранения. Задача проверки общезначимости в логике высказываний co-NP-полна (эквивалентна невыполнимости UNSAT), что при текущем состоянии науки требует в худшем случае экспоненциального времени перебора.

#### Решение Задания 4 (Программы в соответствии Карри — Говарда)

Реализация на языке **Haskell**:

```haskell
-- 1. Коммутативность конъюнкции (произведение типов)
swap :: (a, b) -> (b, a)
swap (x, y) = (y, x)

-- 2. Транзитивность импликации (композиция функций)
compose :: (a -> b) -> (b -> c) -> (a -> c)
compose f g = \x -> g (f x)

-- 3. Разбор случаев дизъюнкции (тип суммы Either)
eitherElim :: Either a b -> (a -> c) -> (b -> c) -> c
eitherElim (Left x)  f _ = f x
eitherElim (Right y) _ g = g y
```

Реализация на языке **TypeScript**:

```typescript
// 1. (A ∧ B) → (B ∧ A)
function swap<A, B>(pair: [A, B]): [B, A] {
    return [pair[1], pair[0]];
}

// 2. (A → B) → ((B → C) → (A → C))
function compose<A, B, C>(f: (a: A) => B): (g: (b: B) => C) => (a: A) => C {
    return (g) => (a) => g(f(a));
}

// 3. (A ∨ B) → ((A → C) → ((B → C) → C))
type Either<A, B> = { kind: 'left'; value: A } | { kind: 'right'; value: B };

function caseAnalysis<A, B, C>(
    disj: Either<A, B>,
    caseA: (a: A) => C,
    caseB: (b: B) => C
): C {
    if (disj.kind === 'left') {
        return caseA(disj.value);
    } else {
        return caseB(disj.value);
    }
}
```
